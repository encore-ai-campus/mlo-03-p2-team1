### 3-2. 연결 컬럼 (이전·교체)

"이 레코드의 개업이 어느 레코드를 이어받았나"를 **뒤 레코드에만** 적습니다. 이전과 교체가 같은 형식입니다.

| 컬럼 (가칭) | 값 |
|---|---|
| `MOVE_PRE_KEY` | 이전해 오기 전 레코드의 `LCNS_KEY` [F3] |
| `REPL_PRE_KEY` / `REPL_TYPE_CD` | 같은 자리의 앞 레코드 `LCNS_KEY` / `재등록` 또는 `교체` [F1]·[F2] |

- 앞 레코드에는 아무것도 적지 않습니다. "이 레코드의 폐업이 이전·교체로 이어졌나"는 자기 `LCNS_KEY`가 다른 행의 `*_PRE_KEY`에 있는지로 압니다.
- 세 곳 이상 옮긴 경우도 바로 앞 레코드만 적으면 차례로 따라갈 수 있습니다.
- 한 레코드가 이전 쪽과 교체 쪽에 동시에 걸려도(옮겨 간 자리에 다른 가게가 들어옴) 두 컬럼이 따로라서 겹치지 않습니다.
- 연결은 1:1입니다. 몇 개까지 허용하는지는 [F0] ④에 있습니다. 그래서 별도 테이블 없이 컬럼으로 둡니다.
- 이전 유형은 지금 한 가지(원래 인허가일 유지 + 전화번호 일치)뿐이라 유형 컬럼을 두지 않습니다.

### 3-5. 골드와의 경계

- 골드는 03 silver를 직접 읽지 않고 **진입 함수**를 거쳐 읽습니다. 진입 함수는 위 컬럼과 정의표·파라미터를 읽어 업소 1행(개업일, 폐업일, 재고 포함, 개업 구분, 폐업 구분 등)으로 돌려줍니다.
- 이전·교체의 앞 레코드를 찾는 계산(`*_PRE_KEY` 조회)도 진입 함수가 한 번만 합니다.
- 진입 함수의 컬럼 약속과 구분 값은 골드 문서에서 정합니다. 다만 집계 기준은 실버와 골드가 같이 지켜야 하므로 고정합니다 → **`07_데이터모델_ERD와_Gold.md` 4장 "골드 집계 기준 (고정)"** (원본 `silver_정제.md` 3-6, L118–131).
- `report/`는 기록 전용입니다. 진입 함수와 골드는 읽지 않습니다.

### A. 원천 선택

> 출처: L196–210

**[A1] 일반음식점: API 본체 + CSV 보완**
- bronze와 02 silver에는 원천 두 개가 그대로 따로 있습니다: `food_general`(API XML), `food_general_file`(CSV, OA-16094).

### D. 법정동 부여

> 출처: L297–324

**[D1] 순서:** 처음 성공한 값을 `LDONG_CD`에 넣고 출처를 적습니다.
1. **일반음식점만:** CSV의 `LDONG_CD` ([A1]). 2017년 이후 영업한 업소의 96.2%에 값이 있고 모두 현행 코드입니다. 지번 파싱 결과와 99.83% 일치하며, 불일치는 대형 건물에서 나옵니다. 행정 시스템의 값이므로 원본을 우선합니다.
2. **`JIBUN_ADDR`:** "서울(특별)시 + 구 + 동명"에서 (구, 동명)을 뽑아 `ldong_code`와 매칭합니다. 동명은 `~가`(종로6가)로도 끝나므로, 접미사가 아니라 코드표에 있는 이름인지로 판단합니다.
3. **`ROAD_ADDR`:** 괄호 안 첫 동명(`율곡로 286 (종로6가)` → 종로6가)과 구로 매칭합니다.

범위를 "2017년 이후 영업한 적 있는 업소"로 재면, 의원·약국은 지번만으로는 부족합니다.

|---|---:|---:|---:|---:|

| 약국 | 9,215 | **88.0%** | 99.8% | 17 |
| 일반음식점 | 252,351 | 99.9% | 100.0% | 12 |
| 휴게음식점 | 94,496 | 99.8% | 100.0% | 46 |
| 미용업 | 58,847 | 99.9% | 100.0% | 4 |

- 지번과 도로명이 둘 다 매칭되는데 동이 다른 건(업종별 7~31건)은 지번을 우선하고, `issue_list`(`ADDR_MISMATCH`)에 두 코드를 남깁니다.

**[D2] 행정동식 동명:** 실패의 대부분은 법정동 대신 행정동 이름이 들어간 경우입니다(상일제1동, 방이1동 등, 의원·약국 약 50건). `제N동`·`N동`을 `동`으로 바꾼 이름이 코드표에 있으면 매칭하고, 출처를 `지번_정규화`/`도로명_정규화`로 둡니다. 그래도 남는 건은 03에서는 출처 `실패`로 둡니다. 좌표로 법정동을 찾는 것은 좌표 변환 단계에서 검토합니다.

**[D3] 서울 밖 주소:** 전체 기간 업종별 1~14건, 합계 33건(예: `경기도 수원시 영통구 원천동 593`).
- `LDONG_CD`는 비우고, 출처를 `실패_서울밖`으로 두고, `OUT_SEOUL_ADDR_YN`을 붙입니다.
- 행은 지우지 않습니다. `LGOV_CD`(개방자치단체코드)는 5개 업종 모두 빈 값이 없고 25개 구청에 대응하므로, **구 단위 집계에는 남깁니다.** 코드 → 구 대응표(25행)는 `metadata/`에 둡니다.
- 2017년 이후 영업한 적 있는 행이 24건입니다(일반음식점 11, 휴게음식점 7, 의원 2, 약국 0, 미용업 4). 지번주소를 먼저 보고 없으면 도로명주소로 판단하며, 지번·도로명 중 하나라도 서울 밖인 행으로 세어도 같습니다.
- 그중 의원 2건은 서울 밖으로 옮긴 전출 의원이라 [D4]가 먼저 적용되어 `실패_전출주소`가 됩니다. 따라서 `OUT_SEOUL_ADDR_YN`이 붙는 행은 22건입니다.
- 정정 (2026-11-20): 원본은 28건이었으나 계산 근거가 남아 있지 않고 02·03 데이터로 재현되지 않아 24건으로 고쳤습니다.

**[D4] 전출 의원의 새 주소:** 전출 812건 중 10건은 주소가 전출한 뒤의 새 주소로 갱신되어 있습니다(`LGOV_CD`의 구 ≠ 주소의 구). 전출이 아닌 의원에서는 이런 불일치가 0건입니다. 이 10건은 주소로 법정동을 붙이지 않고, 출처를 `실패_전출주소`로 두고 구 단위로만 집계합니다.

### F. 교체·재등록·이전

> 출처: L367–446 (근거 데이터: `03_원천데이터_점검과_재구성_검증.md` 4장)

**범위:** 실제 이전·재등록 이력을 완벽하게 복원하지 않습니다. 근거가 명확하고 **양쪽 후보가 하나뿐인 경우만** 연결하고, 나머지는 원본 날짜를 그대로 두고 `issue_list`에 남깁니다. 내려놓은 부분은 7장 "한계"에 있습니다.

이전과 교체·재등록은 3-2의 연결 컬럼으로 표시합니다. 뒤 레코드(B)에 앞 레코드(A)의 `LCNS_KEY`를 적습니다.

**[F0] 연결 공통 규칙**

| 단계 | 내용 |
|---|---|
| ① 후보 찾기 | [F1]·[F2]·[F3]의 조건으로 종류마다 **따로** 찾습니다 |
| ② 시간 조건 | A는 분석용 폐업일이 있는 종료 레코드. **B의 분석용 개업일 > A의 분석용 개업일** (모든 종류 공통, 순환 방지). 이전 [F3]은 확정 전에는 B의 **예상** 개업일(= A의 분석용 폐업일)로 검사하고, 확정 후 최종 날짜로 완료 조건 6에서 다시 검증합니다 |
| ③ 확정 | 이전 → 재등록 → 교체 순서로 확정합니다. 각 종류에서 **A의 후보도 B 하나, B의 후보도 A 하나**일 때만 확정합니다. 동률이거나 후보가 여럿이면 연결하지 않고 `issue_list`(`AMBIG_LINK`)에 남깁니다 |
| ④ 사용 제한 | B의 앞 레코드: 이전·교체·재등록을 합쳐 **최대 1개** / A의 이전 뒤 레코드: 최대 1개 / A의 교체·재등록 뒤 레코드: 최대 1개 |

- ④ 때문에 B가 A를 이어받은 뒤 다시 C의 앞 레코드가 될 수 있습니다(A → B → C). A가 이전하면서 그 자리에 다른 업소가 들어오는 경우(A의 이전 뒤 + 교체 뒤)도 표현됩니다.
- ②를 만족하지 못한 후보는 `issue_list`(`TIME_CONFLICT`)에 남깁니다.
- ② 조건이 있으면 연결을 따라갈수록 개업일이 계속 늦어지므로, 순환이 생길 수 없습니다.
- 전화번호는 자리표시 값과 빈 값을 빼고 비교합니다([C6]).

**[F1] 재등록 (`REPL_PRE_KEY`, `REPL_TYPE_CD` = `재등록`)**
- **조건:** 같은 원천 업종, 같은 상호(공백·괄호·특수문자·U+FFFD 제거 후 비교), **같은 `LDONG_CD` + 본번-부번**, B의 `LCNS_DTM`이 A의 분석용 폐업일 ±7일 안.
- 교체와 **따로** 찾습니다. 주소 문자열이 아니라 번지로 비교해서, 표기만 다른 같은 자리(예: `대치동 1002번지 지하1층` ↔ `대치동 1002 (주)케이티앤지 타워`)도 후보가 됩니다. 약국 2017년 이후 후보 규모는 524건이고, 최종 연결 수는 03 결과로 다시 셉니다.
- 법정동 부여에 실패한 행은 번지를 비교할 수 없어 후보에서 빠집니다(건수는 `change_log`).
- 약국은 옮길 때 새 인허가일로 다시 등록합니다(2017년 이후 약국 신규의 약 26%). 재고에는 영향이 없지만 개업·폐업 수에는 영향이 커서 이 규칙을 둡니다.

**[F2] 교체 (`REPL_PRE_KEY`, `REPL_TYPE_CD` = `교체`)**
- **조건:** 같은 원천 업종, **같은 `JIBUN_ADDR`**(공백만 정리), **다른 상호**, B의 `LCNS_DTM`이 A의 분석용 폐업일 ±7일 안.
- 재등록으로 이미 앞 레코드가 정해진 B는 후보에서 뺍니다(④).
- 비율(분석범위 제안서): 2017~2025 신규 인허가 중 같은 지번 ±7일은 약국 9.4%, 미용업 8.9%, 일반음식점 14.7%, 휴게음식점 18.8%.

|---|---|---|
| 약국 A | | |
| 약국 B (같은 상호, 같은 번지, 같은 날) | A의 `LCNS_KEY` | 재등록 |

**[F3] 구 간 이전, 원래 인허가일 유지 (`MOVE_PRE_KEY`)**

**조건 (모두 만족)**
1. 같은 원천 업종, 같은 상호, **같은 `LCNS_DTM`**, 다른 `LGOV_CD`
2. **유효한 전화번호 일치** (자리표시·빈 번호 제외). 상호·인허가일만 같은 것은 연결하지 않습니다. 프랜차이즈와 백화점 지점 때문에 오판정 위험이 큽니다(예: '가마솥진국'은 영등포·서초 신세계백화점에 인허가 2021-03-09, 폐업 2021-03-25로 같은 레코드가 있음).
3. **B의 분석용 종료일 > A의 분석용 종료일** (B가 영업 중이면 통과). 종료일이 같으면 이전이 아닙니다.
4. 같은 묶음(상호 + 인허가일)을 종료일 순으로 정렬해 **바로 이웃한 레코드끼리만** 잇습니다. 종료일이 같은 레코드가 있거나 순서가 불명확한 묶음은 통째로 연결하지 않고 `AMBIG_LINK`로 남깁니다.

이 유형은 B의 인허가일이 실제 이전일이 아니라서, 날짜 차이로 짝을 고르지 않습니다.

**시간 검사 순서:** A와 B의 인허가일이 같으므로, B의 원본 개업일로 [F0] ②를 검사하면 모든 후보가 탈락합니다. 그래서 확정 전에는 B의 예상 개업일(= A의 분석용 폐업일)로 검사하고(사실상 "A의 영업 기간 > 0일"), 확정한 뒤 바뀐 최종 날짜로 완료 조건 6에서 다시 검증합니다.

**처리**
- B의 분석용 개업일 = A의 분석용 폐업일, 출처 `이전_앞레코드종료일`. 원본 `LCNS_DTM`은 보존합니다.
- B의 `MOVE_PRE_KEY` = A의 `LCNS_KEY`. A에는 적지 않습니다.
- 결과: 원래 구에는 A의 종료일까지, 새 구에는 그날부터 잡혀서 겹치지 않습니다.

**기록 (`change_log`)**
- 종류별 확정·미확정(`AMBIG_LINK`, `TIME_CONFLICT`) 건수
- **연결 전후 분기 말 재고 차이** (업종별). 이전 연결로 줄어든 이중 집계 규모를 보여 주고, 연결하지 못한 후보가 남긴 편향은 7장에 한계로 적습니다.
